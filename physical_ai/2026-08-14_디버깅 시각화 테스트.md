### [16강] 디버깅 시각화 테스트

-   **디버깅**
	-  노드 토픽 연결 구조 확인: `rqt_graph`
	-  공간, 센서, TF 확인: RViz2
	-  수치변화 (실시간 그래프): `rqt_plot`
	-  문제 재현 (기록 및 재생): `rosbag2`
	-  로그 추적: `rqt_console`

-  자주 쓰는 명령어
```bash
ros2 topic list / echo / hz / info   # 토픽 존재·내용·주파수·QoS
ros2 node list / info                # 노드와 그 연결
ros2 topic pub ...                   # 직접 메시지 주입해 테스트
rqt_graph                            # 노드-토픽 연결 시각화
```
 
- 진단 절차 예시: 인지가 장애물을 놓친다
	- `ros2 topic echo /obstacles` → 인지가 발행하는지 확인
	- `ros2 topic hz /scan` → 센서가 오는지 확인
	- `rqt_graph` → 연결이 됐는지 확인
	- 데이터 흐름을 단계별로 추적하면서 문제 지점을 좁혀갈 것


-  **Marker**
	- 내가 계산한 결과(목표 지점, 장애물 등)를 RViz2에 그리기 위한 메세지
		→ `from visualization_msgs.msg import Marker`
	- RViz2는 토픽에 있는 것만 그리므로, 계산 결과를 보려면 마커 토픽으로 발행해야 함
	
```python
from visualization_msgs.msg import Marker

m = Marker()
m.header.frame_id = 'world'                    # 기준 좌표계 
m.header.stamp = self.get_clock().now().to_msg()
m.ns, m.id = 'waypoints', 0                     # 같은 ns+id는 덮어쓰기
m.type = Marker.SPHERE
m.action = Marker.ADD
m.pose.position.x, m.pose.position.y = 2.0, 3.0
m.pose.orientation.w = 1.0                       # 회전 없음
m.scale.x = m.scale.y = m.scale.z = 0.2          # 0이면 안 보임
m.color.r, m.color.a = 1.0, 1.0                  # alpha 0이면 투명해서 안 보임
self.marker_pub.publish(m)
```

-  RViz2 왼쪽 하단에 있는 `Add` 버튼 → `By topic` 탭 → 마커 토픽 찾아서  추가
-  RViz2의 **Fixed Frame**을 마커의 `frame_id`와 일치시켜야 함
- 마커가 안 보이는 대표 원인 3가지 ⭐
	1) `scale`이 0    (크기가 0인 도형이라 안보임)
	2) `color.a`(alpha)가 0    (값이 0이면 완전 투명, 1이면 완전 불투명)
	3) Fixed Frame 불일치
	
- 여러 점을 한 번에 그릴 때는 `Marker.SPHERE_LIST` 또는 `MarkerArray` 사용
- 여러 정보(LiDAR 장애물, 인지 검출 장애물, TF 센서 위치)를 한 화면에 겹쳐 보면 좌표 변환 오류남

### 실습 - rosbag 2

-  rosbag2: 현장에서 발생한 문제를 기록 및 재생
	-  토픽 메세지를 타임스탬프와 함께 파일로 기록 (record) → 나중에 재생 (play)

```bash
ros2 bag record /scan /image /tf         # 지정 토픽 기록 (-a는 전체)
ros2 bag record -a -o field_test_01      # 전체를 이름 붙여 기록
ros2 bag play field_test_01              # 재생
ros2 bag info field_test_01              # 내용 요약(토픽·기간·메시지 수)
```

**예외 처리**

```python
def on_scan(self, msg):
    try:
        d = self.nearest(msg)                       # 실패할 수 있는 계산
    except (ValueError, ZeroDivisionError):          # 대응 방법을 아는 예외만
        self.get_logger().warn('스캔 한 프레임 건너뜀')
        return                                       # 다음 주기에 다시 시도
    self.publish(d)
```

-  예외는 좁게 잡기 (`except Exception`으로 뭉뚱그리면 내가 만든 버그도 삼켜지기 때문)
-  복구 불가한 실패는 살려 두지 않고 정지 명령 후 종료시킬 것
-  `finally` 또는 `destroy_node()` 직전에 정지 명령, 포트 정리로 안전한 종료 경로 확보하기
-  로그는 `print` 대신 **노드 로거** 사용 → 레벨별로 `rqt_console`에서 필터링 가능

### 테스트

-  **단위 테스트** - pytest (python), gtest (c++)

-  pytest
```python
# test_safety.py
from robot_utils.safety import compute_stop_distance

def test_stop_distance_zero_speed():
    assert compute_stop_distance(0.0) == 0.0

def test_stop_distance_increases_with_speed():
    assert compute_stop_distance(2.0) > compute_stop_distance(1.0)

def test_stop_distance_formula():
    # v=1.0, decel=1.5 → 1.0/(2*1.5)
    assert abs(compute_stop_distance(1.0) - 1/3) < 1e-6
```

```bash
pytest test_safety.py -v
```

-  gtest

```cpp
#include <gtest/gtest.h>
#include "robot_utils/safety.hpp"

TEST(SafetyTest, ZeroSpeed) {
  EXPECT_DOUBLE_EQ(computeStopDistance(0.0), 0.0);
}
TEST(SafetyTest, IncreasesWithSpeed) {
  EXPECT_GT(computeStopDistance(2.0), computeStopDistance(1.0));
}
```
