### row_echelon 함수 및 det 함수 구현

- 왜 상삼각행렬의 행렬식은 대각원소 곱인가 ⭐
- 2차원 행렬 A에 대해 `row_echelon`이 만든 U는 피벗 아래가 전부 0인 상삼각행렬. 3×3 예시로 det 계산해봄

```
U = [ a₁₁ a₁₂ a₁₃ ]
    [  0  a₂₂ a₂₃ ]
    [  0   0  a₃₃ ]

det(U) = a₁₁(a₂₂a₃₃ − 0) − a₁₂(0 − 0) + a₁₃(0 − 0)
        = a₁₁ · a₂₂ · a₃₃
```

- 결론: `det(A) = diag(U)의 곱` → `np.prod(np.diag(U))` 이용
- `det(A) = (-1)**swaps * np.prod(np.diag(U))` - 행 교환으로 인한 부호 반전(`swaps`)과 상삼각 구조로 인한 대각곱 두 요소가 왜 필요한지 유도 과정을 통해 확인할 수 있었다


### C++ 공부

**포인터·참조·const**
- `const std::string& label`: `&`(복사 없이 참조) + `const`(값 변경 X)
    - `const` 없으면 문자열 리터럴 넘기는 코드 자체가 **컴파일 안 됨** — 리터럴로 만들어지는 임시 객체는 `const` 참조에만 바인딩 가능하기 때문 ⭐

#### CMake와 증분 빌드
- `add_executable(타겟이름 소스파일들...)`: `g++` 컴파일+링크 수작업을 CMake가 대신 하도록 선언
- 증분 빌드: `make`가 소스와 대응 `.o`의 수정 시각(mtime)을 비교, 바뀐 파일만 재컴파일함 (링크는 오브젝트 하나라도 바뀌면 매번 수행)
- `motor.o`(수동 빌드 시 직접 지정한 이름) vs `motor.cpp.o`(CMake 자체 명명 규칙, 확장자까지 남겨서 이름 충돌 방지)
