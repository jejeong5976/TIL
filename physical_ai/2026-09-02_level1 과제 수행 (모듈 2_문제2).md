### 가상 소멸자 & 다형성  루프

- 순수 가상 함수(`virtual double read() = 0;`)로 `Sensor` 추상 클래스를 만들고, `Lidar`/`Imu`가 이를 구현하는 계층 구조로 설계
- 핵심 원리: **가상 소멸자는 "베이스 클래스 포인터/참조로 파생 객체를 다룰 때만" 문제가 됨**
	- 스택 객체(`Lidar stack_lidar;`)나 `unique_ptr<Imu>`는 컴파일 타임에 실제 타입이 확정되므로 `virtual` 여부와 무관하게 항상 올바르게 소멸됨
	- 문제는 `Sensor* s = new Lidar();`처럼 **베이스 타입으로 감싸서** `delete`할 때 발생

- **실습으로 확인**

| 상황 (sensor.hpp)        | 결과                                                              |
| ---------------------- | --------------------------------------------------------------- |
| `virtual ~Sensor()` 있음 | `~Lidar()` → `~Sensor()` 순서로 정상 호출                              |
| `virtual` 제거           | `~Lidar()` 호출 안 됨, `~Sensor()`만 호출 → 파생 클래스가 자원을 갖고 있었다면 누수로 직결 |

- `override`: 실제로 재정의하는지 컴파일러가 검증함
	- **실험**: 베이스 소멸자에서 `virtual`만 빼고 파생 쪽 `override`는 남겨두면 `marked 'override', but does not override` **컴파일 에러** 발생
	- `override`까지 지우면  경고만 뜨고 컴파일 되고, 프로그램이 정상적으로 실행되는 것처럼 보임
	  (실제 문제는 ASan 등으로 메모리 누수 검사를 하기 전까지 드러나지 않음)
		→ `override`를 항상 붙이는 습관을 들여야하는 이유

> 가상 소멸자가 없으면 `~Lidar()` 호출이 스킵되면서 `Lidar`가 내부적으로 들고 있던 자원을 정리하는 코드가 실행되지 않음 (파생 클래스 소멸자가 호출되지 못해서) → 데이터 누수


### 스택과 힙

**스택**
- 함수 호출과 자동으로 맞물려 움직이는 메모리 - 함수 호출마다 자동 확보/해제
- 포인터만 움직이면 되므로 매우 빠름
- 함수가 끝나면 소멸
- 할당 방법: 지역 변수 선언 자체가 스택 생성

**힙**
- 실행 중 원하는 크기로 할당 (동적 할당 영역)
- 할당/해제가 느리고, 시간이 불규칙함 (지터의 원인)
- 함수가 끝나도 소멸되지 X → 해제를 잊으면 메모리 누수 발생
- 할당 방법: `new` 혹은 `make_unique` 같은 함수를 명시적으로 호출해야 생성


### `unique_ptr`

- 힙 객체도 스택처럼 자동으로 소멸되게 할 수 있는 스마트 포인터
- 복사 금지(소유권 단일화) + 이동만 가능 → 이중 해제(double free) 방지
- 스코프를 벗어나거나 `.reset()` 호출 시 자동 `delete`됨
- **원시 포인터와의 차이**: `Lidar* s = new Lidar();`처럼 만들고 안 쓰면 `-Wunused-variable` 경고가 뜨지만, `unique_ptr`는 안 써도 경고가 안 뜸


### ASan으로 메모리 누수 검출 ⭐

- `#ifdef FIXED` 전처리기 매크로로 한 파일 안에서 누수 버전/수정 버전을 컴파일 옵션(`-DFIXED`)으로 전환할 수 있게 함
- ASan(`-fsanitize=address`)
	- valgrind와 달리 별도 설치 없이 컴파일러 옵션 하나로 활성화 가능
	- `new`/`delete` 추적 후 종료 시 미해제 메모리를 바이트 수·객체 수·소스 위치까지 자동 리포트
