## 알게 된 것

- **벡터화 사고방식**
    - 반복문으로 원소 하나씩 처리하는 대신 **"조건 → 마스크 → 집계"** 세 박자로 배열 전체를 한 번에 연산하는 것이 더 효율적 → 실습 결과를 통해 확인 가능
    
- **뷰(view) vs 복사(copy)**
    - 슬라이싱(`scan[0:90]`)은 원본과 메모리를 공유하는 **뷰**라서 잘라낸 부분을 수정하면 **원본도 바뀜**
    - 마스킹(`scan[mask]`)·팬시 인덱싱(`scan[idx]`)은 새 메모리를 만드는 **복사**라서 **원본과 독립적임**
    - 따라서 원본 보존이 필요하면 `.copy()`를 명시적으로 붙이는 습관이 필요

- **브로드캐스팅**
    - shape가 다른 배열끼리도 **뒤에서부터** 차원을 짝지어 **같거나 한쪽이 1이면** 자동으로 늘려서 연산 가능
    - `(N, 3) @ R.T` 같은 행렬곱으로 **N개의 점을 반복문 없이 한 번에 회전**시킬 수 있다는 것을 실습에서 직접 확인함 (회전 후에도 `np.linalg.norm`으로 거리 보존 검증)

- **자료구조 선택 기준**
    - 순서·중복 필요 → **list** / 불변 묶음 → **tuple** / 이름으로 조회 → **dict** / 소속·중복제거 → **set**
    - 시간 복잡도에 따라 주기와 지터 문제에 직결될 수 있음

- **가변 기본 인자 함정⭐**
    - `def f(log=[])` 처럼 리스트를 기본값으로 두면 **함수 정의 시점에 단 한 번만 생성**되어 호출들끼리 상태가 공유되는 버그가 됨. 
    - `log=None` 후 함수 안에서 새로 생성하는 것이 올바른 관용구
