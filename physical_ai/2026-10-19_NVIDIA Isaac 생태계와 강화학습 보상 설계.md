### NVIDIA 로봇 생태계와 GPU 하드웨어

- **생태계 3층**
	- GPU 하드웨어: RTX, Jetson, DGX
	- 계산과 모델 실행: CUDA, cuDNN, TensorRT
	- 가상 환경과 로봇 개발: Omniverse, Isaac, GR00T
- **x86 vs ARM**
	- RTX(게이밍 GPU)는 x86 PC용. 최신 그래픽카드는 시스템 전력 1000W 이상 → 배터리로 움직이는 로봇에 탑재 불가
	- Jetson(Orin Nano, Thor)·DGX(Spark)는 ARM 기반 → 저전력, 온디바이스용
	- 라즈베리 파이는 NVIDIA GPU가 없음 → CUDA 없음 → Isaac ROS 사용 불가
- **멀티 GPU**: RTX 이론상 최대 8개, DGX 최대 2개 장착 → 장착 수↑ = 총 VRAM↑ = 올릴 수 있는 모델 크기↑
	- 데이터센터(OpenAI, Anthropic 등)는 RTX가 아닌 H 계열(H200 등) 서버용 GPU 사용

| 구분 | 아키텍처 | 특징 | 용도 |
| --- | --- | --- | --- |
| RTX | x86 | 고성능·고전력, 최대 8개 장착 | Isaac Sim 실행, Lab 학습 |
| Jetson | ARM | 저전력, CPU·GPU가 시스템 메모리 공유 | 센서 처리, 실제 로봇 구동 |
| DGX (Spark) | ARM | 공유 메모리, 최대 2개 장착 | 로컬 LLM, 연구실 |

- **장치별 역할**: Ubuntu 노트북 = Jetson OS 플래시 / RTX PC = Isaac Sim·Lab / Jetson = 센서 처리·로봇 구동
	- Orin Nano는 Isaac Sim 실행 장치가 아님 ⭐

### CUDA와 CPU/GPU/메모리

- **CUDA**: NVIDIA GPU의 병렬 계산 플랫폼. NVIDIA 독점 → 대부분의 AI 모델이 CUDA에서 최적 성능
	- 로봇에서 쓰는 계산: 영상 처리, 신경망, 병렬 환경(물리 계산)
- **TensorRT**: 학습한 모델의 추론 최적화 도구
- CPU도 계속 사용함: Nav2, Cartographer는 CPU만 / cuVSLAM은 GPU 사용

| 구분 | 주요 역할 | 예시 |
| --- | --- | --- |
| CPU | 순서와 분기가 많은 처리 | ROS 노드, 파일, 작업 관리 |
| GPU | 비슷한 연산을 대량으로 처리 | 영상, 행렬, 물리 계산 |
| VRAM | GPU가 사용하는 메모리 | 모델, 텍스처, 센서 출력 |
| Jetson 메모리 | CPU와 GPU가 시스템 메모리 공유 | 모델과 ROS 노드가 함께 사용 |
| TensorRT | 학습한 모델의 추론 최적화 | 지원 장치에서 모델 실행 |

- **ROM vs RAM vs VRAM**
	- ROM(SSD, HDD, SD카드): 영구 저장, 전원 꺼져도 보존
	- RAM: 임시 저장, 전원 꺼지면 소실. ROM보다 수십 배 빠름 → 연산할 데이터는 RAM에 올려서 처리
	- VRAM: GPU 전용 메모리, 그래픽카드에 내장
- **RAM과 VRAM을 따로 두는 이유**
	- 반도체는 **레티클 한계**(물리적으로 만들 수 있는 최대 크기)가 있음 → 한 칩에 CPU·GPU·RAM을 다 못 넣음 → 메인보드에서 배선으로 연결
	- 배선으로 오가는 데이터가 많을수록 발열↑ → 병렬 처리 데이터가 많은 GPU는 자체 VRAM 장착 ⭐
- **HBM**(High Bandwidth Memory): 메모리 다이를 세로로 쌓아 대역폭을 높인 기술. SK하이닉스가 세계 최초 개발
- **공유(통합) 메모리**: RAM과 VRAM을 하나로 → Jetson, DGX Spark, Apple M 시리즈
	- 조건: ARM 아키텍처 필수(x86 불가), 저전력 설계, 단일 칩 통합

### 계산 속도와 로봇 반응 속도

- 처리 흐름: 카메라 입력 → 전처리 → 연산(추론) → 발행
- 느린 단계를 찾을 때 GPU 연산만 보지 말고 **메모리 복사와 CPU 처리**도 관찰
- 측정 지표: 초당 처리량 + 입력부터 출력까지 걸리는 지연(end-to-end latency) → 로봇 반응 속도를 결정
- Jetson 기준 인식 주기 약 `20~30Hz` (RealSense 기본 `30fps`에 맞춤) → CPU로는 감당이 어려워 GPU 사용
- 도구 예: NVIDIA Nsight

### Isaac Sim / Isaac Lab / Isaac ROS

- 시뮬레이션이 필요한 이유: 학습 중인 로봇은 검증 안 된 움직임을 함 → 현실에선 위험
	- 특히 전력 위험: 요즘 휴머노이드 액추에이터는 `48V` 계열 모터 → 감전·화재 위험

| 도구 | 담당하는 작업 | 대표 결과물 |
| --- | --- | --- |
| Isaac Sim | 가상 로봇과 센서를 시험 | 장면, 센서 데이터, 시험 기록 |
| Isaac Lab | 학습 실험과 정책 평가 | 정책 체크포인트, 실험 로그 |
| Isaac ROS | ROS 2에서 가속 기능 실행 | 인식, 위치, 지도 등의 메시지 |

- **Isaac Sim** (Omniverse 기반)
	- 가상 로봇 구성: 형상·관절(URDF 또는 USD 자산) / 물리 설정(질량, 충돌, 마찰, 관절 한계) / 센서·제어(카메라와 제어 명령 연결)
	- URDF는 USD로 변환해서 사용 (자동 변환 가능)
	- OpenUSD: 장면(Scene)과 여러 자산을 조합하는 기반
	- 물리 환경은 직접 정의: 조도·광원 위치, 물체 무게·재질, 바닥 재질, 바람, 그리퍼 재질, 센서 노이즈, 모터 피크/평균 전류
	- 합성 데이터: RGB·깊이·분할 출력 + 가상 환경 상태로 정답 라벨 자동 생성 → 실제 수집·라벨링을 **보완**
	- 합성 데이터만 쓰지 않고 실제 데이터와 섞음 (예: Isaac Sim 9,000장 + 실촬영 1,000장) ⭐
- **Isaac Lab**
	- 정의할 것: 관측(observation), 행동(action), 보상(reward), 종료(termination)
	- 학습 흐름: 환경·관측·행동 구성 → 학습 라이브러리 연결 → 정책·로그 저장 → 새 조건에서 평가
	- 병렬 환경: 같은 과제를 여러 환경에서 동시에, 환경마다 상태·시작점은 다름 → 환경 수↑ = 경험↑, VRAM 사용↑
	- 3.0 계열은 여러 물리 백엔드 지원 (Isaac Sim PhysX, Newton)
- **Isaac ROS**: 대부분 CPU로 도는 ROS 2 패키지에 NVIDIA GPU 가속을 붙이는 도구
	- 사용 예: cuVSLAM, AprilTag, DNN 추론
	- Node·Topic·TF·시간 개념은 ROS 2와 동일
- 프로젝트 2: Isaac Sim에서 학습한 모델 → Isaac ROS + Nav2로 자율주행

### VSLAM / VLM / VLA / GR00T

- VSLAM: 카메라로 지도와 위치를 함께 추정 / cuVSLAM: NVIDIA의 GPU 가속 VSLAM / Nav2: 위치·지도·장애물로 주행 계획
- 위치 추정 조건: 카메라 보정값과 TF가 맞는지, 특징점이 보이고 측정 시각이 맞는지, 위치 추정과 주행용 지도를 구분하는지

| 용어 | 주요 입력 | 출력 |
| --- | --- | --- |
| VSLAM | 연속 영상과 센서 정보 | 기하학적 지도와 위치 추정 |
| VLM | 영상과 언어 | 장면 설명과 질의 응답 |
| VLA | 영상, 지시, 로봇 상태 | 로봇 행동 또는 행동 토큰 |

- 세 가지는 결과물이 다름: 지도·위치 / 장면 설명 / 행동 생성 ⭐
- VLA 출력은 로봇마다 규격이 달라서 로봇별 변환과 제어기가 필요
- **GR00T**: NVIDIA 로봇 행동 모델·개발 도구. 행동 표현은 관절 목표 또는 말단 이동량 등 (레벨 3에서 다룸)

### 강화학습 기본 구조

- 정책이 관측을 보고 행동을 고름 → 환경이 결과와 보상을 돌려줌 → 경험을 쌓아 장기적으로 좋은 결과를 내는 정책을 학습

| 용어 | 뜻 | Cartpole 예시 |
| --- | --- | --- |
| Agent / Policy | 행동을 고르는 주체와 규칙 | 카트를 제어하는 신경망 |
| Environment | 행동의 결과가 생기는 환경 | 카트와 막대 물리 계산 |
| Observation | 정책이 읽는 정보 | 위치, 속도, 각도 |
| Action / Reward | 제어 입력과 평가 신호 | 힘 입력과 균형 유지 보상 |
| Episode | 초기화부터 종료까지 한 시도 | 시작 후 실패 또는 시간 종료 |

- **Cartpole**: 관측 = 카트 위치·속도, 막대 각도·각속도 / 행동 = 카트를 미는 힘 / 목표 = 막대가 넘어지지 않게 균형 유지
- **PPO**: 경험 수집(관측·행동·보상 기록) → 모은 경험으로 정책을 **조금씩** 갱신
	- Lab은 환경 담당, 최적화는 학습 라이브러리 담당

| 단계 | 하는 일 | 저장하거나 측정할 것 |
| --- | --- | --- |
| 학습 | 경험 수집 후 정책 파라미터 갱신 | 보상, 손실, 체크포인트 |
| 추론 | 고정된 정책으로 행동 생성 | 행동과 실행 시간 |
| 평가 | 새 조건에서 반복 시험 | 성공률, 충돌, 실패 유형 |

- 보상 곡선만 보지 말고 **실제 성공률도 함께** 확인
- 휴머노이드 확장 방식(강사 예시): 평지에서 먼저 학습 → 그 모델로 계단 → 험지 순서로 추가 학습

### 보상 함수 설계와 Reward Hacking

- 같은 로봇이어도 보상 함수를 어떻게 짜느냐에 따라 움직임이 완전히 달라짐
- **이동 로봇 학습 과제 설계**

| 항목 | 교육용 예시 | 점검할 질문 |
| --- | --- | --- |
| 관측 | 목표 방향, 거리, 속도, 장애물 거리 | 실제 로봇에서도 얻을 수 있나? |
| 행동 | 전진 속도와 회전 속도 목표 | 속도와 가속 한계 안에 있나? |
| 보상 | 목표 접근, 도착, 충돌 | 점수만 얻는 편법은 없나? |
| 종료와 초기화 | 도착, 충돌, 시간 종료 / 시작점 변경 | 새 조건에도 성공하는가? |

- **보상 설계 예시**

```
r_step = 2 × (목표 접근 거리) − 0.01 × (경과 시간)
도착 시 +10 / 충돌 시 −20
```

- **Reward Hacking**: "앞으로 가라"만 보상하면 원점(`base_footprint`) TF가 x축으로 이동하기만 하면 성공 처리 → 걷지 않고 넘어지거나 빙글빙글 돌면서 전진 ⭐
	- 해결: 보상을 잘게 쪼개 **어떻게** 움직였는지(관절별 움직임, 동역학적으로 타당한지)까지 넣음
- 보상은 늘었는데 충돌도 늘었다면 → 점수만 얻는 편법인지, 충돌 페널티·종료 조건이 제대로 걸리는지 확인

### 모방학습과 Sim to Real

- **모방학습**: 시연 데이터에서 관측→행동 관계를 학습 / **강화학습**: 상호작용과 보상으로 행동 개선
	- 시연으로 시작한 뒤 강화학습으로 추가 학습하는 흐름이 표준 → 모방학습 결과가 강화학습 보상의 기준치로도 쓰임
	- 시연 수집: Isaac Teleop, VR 기기, 리더-팔로워 로봇팔
	- 실습 예정: Dynamixel 리더/팔로워 → 토크 OFF 상태에서도 엔코더 값을 읽을 수 있어 손으로 움직인 궤적을 기록 가능
	- 하드웨어·강화학습보다 자본이 적게 들어 국내 피지컬 AI 스타트업이 많이 하는 분야

- **Sim to Real**

| 구분 | 내용 |
| --- | --- |
| 차이가 생기는 곳 | 마찰, 질량, 모터 응답, 센서와 지연 |
| 도메인 랜덤화 | 조건을 바꿔가며(이상적 ~ 극한 환경) 다양한 경험 제공 |
| 배포 확인 | 단위, 순서, 행동 스케일, 제어 주기 |

- 시뮬레이터가 현실을 100% 재현해도 실데이터가 필요한 이유: 같은 장면도 센서(RealSense / 웹캠 / 폰 카메라)마다 데이터가 다름

## 알게 된 것

- Isaac 3종은 역할이 분리되어있음
	- 카메라 위치 시험 → Sim, 정책 학습 → Lab, 실제 영상 가속 → ROS
- RAM/VRAM 분리는 레티클 한계와 발열 때문이고, 공유 메모리(Jetson·DGX Spark·M 시리즈)는 ARM 기반이어야 가능함
- 로봇 반응 속도는 GPU 연산 시간이 아니라 입력→발행까지의 전체 지연으로 봐야 하고, 메모리 복사·CPU 처리도 병목이 될 수 있음
- 보상 함수가 결과만 보면 AI는 점수만 따는 편법을 찾음 → 어떻게 움직였는지를 보상에 넣고, 보상 곡선과 실제 성공률을 같이 봐야 함
- 모방학습으로 시작 → 강화학습으로 추가 학습이 표준 흐름이고, Sim2Real 격차는 도메인 랜덤화와 배포 시 단위·스케일·제어 주기 확인으로 줄임 ⭐
