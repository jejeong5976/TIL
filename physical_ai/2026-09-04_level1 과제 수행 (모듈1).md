**마크다운 이미지 문법 실수**

| 스타일 | 문법          | 특징                                       |
| :-- | :---------- | :--------------------------------------- |
| 인라인 | `![설명](경로)` | 바로 렌더링됨                                  |
| 참조  | `![설명][경로]` | 별도 `[경로]: url` 정의 없으면 GitHub에서 이미지 안 뜸 ⭐ |
- `report.md`에 이미지 파일을 참조 스타일로 작성해뒀던 것을 인라인으로 수정함


**Git 워크플로우: 브랜치 → PR → merge → 로컬 동기화**

```text
feature 브랜치(docs/module1) 생성
→ 작업
→ PR 오픈 + 리뷰
→ main으로 merge
→ (로컬) git pull origin main
```

- 웹에서 merge해도 **로컬 main은 자동으로 업데이트되지 않음** ⭐ → `git pull origin main`으로 직접 받아와야 함
- 이걸 안 하고 로컬 브랜치를 지우면 `git branch -d`가 "HEAD에 병합 안 됨" 경고를 띄움
	- 즉, 로컬 main이 최신 상태가 아니라서 Git 입장에서는 그 브랜치 내용이 아직 안 합쳐진 것처럼 보임


**Git tag: 커밋을 고정해서 마킹** ⭐

- 브랜치처럼 커밋을 따라 움직이지 않고, **특정 커밋 하나를 영구 고정**
- 과제 "제출 시점"을 표시하는 용도로 사용 (예: `lv1-module1-submit`)
- 마감 전까지 수정 가능성이 있으면 태그는 **맨 마지막에** 찍는 게 안전
- 필요하면 태그 삭제 후 재생성 가능

### 알게 된 것

- 참조 스타일 이미지 문법은 별도 정의가 없으면 렌더링 자체가 안 됨
  → GitHub에 올릴 때는 인라인 스타일을 기본으로 습관화할 것
- PR을 웹에서 merge한 뒤에는 반드시 로컬에서 `git pull`로 동기화해야 브랜치 정리할 때 경고 피할 수 있음 (로컬에서 main이 update됨)
- 제출용 태그는 수정 가능성이 남아있는 동안 찍지 말고, 최종 확정된 시점에 찍는 것이 안전함
