### 1. 도메인 랜덤화(DR)

- **개념**
	- 환경 파라미터를 분포 p(ξ)에서 뽑아 여러 조건을 경험시키며 정책을 학습함
	- 단일 장면 학습은 조명·배치·물리가 바뀌면 실패할 수 있음
	- 환경 하나에 로봇 하나를 두고, 환경을 랜덤화해 병렬 학습
	- 완전 무작위가 아니라 **일반화 가능한 범위 안에서** 랜덤화함 ⭐
	- DR은 실물 성공을 보장하지 않으므로 실물 성능은 별도 시험으로 확인

- **랜덤화 네 계열** (시각이 가장 중요함: 어떤 조명·카메라·색에서도 물체를 인식해야 함)

| 계열 | 예 | 근거(강의 예시) |
| :--- | :--- | :--- |
| 시각 | 표면 재질, 조명 색·세기·방향, 카메라 내부 파라미터·마운트 오차 | 3D 프린터 출력물은 표면이 균일하지 않음 |
| 물리 | 질량, 마찰(손가락-물체, 관절), 감쇠, 관성 | 출력물마다 무게가 다름 |
| 시스템 | 행동 지연, 제어 주기, 센서 노이즈 | 제어 주기가 일정하지 않음 |
| 초기 조건 | 로봇 초기 자세, 물체(목표) 위치 | 외력으로 자세가 틀어져도 대응해야 함 |

- **범위 설정 원칙** ⭐
	- 중심은 측정한 공칭값, 폭은 반복 측정과 모델 잔차로 정함
	- **단위·상한·하한·근거를 기록함** (임의 값 사용 금지)
	- 물리 값은 현실에서 가능한 범위만 사용함 (중력가속도에 1을 넣을 수 없음)
	- 센서 노이즈 상한은 엔코더 1 step 분해능 기준 (그 이상의 편차는 오차가 아니라 오류로 봄)
	- 관성은 물체는 전 팀 공통, 팔은 거꾸로 장착한 팀처럼 링크 구성이 다를 때만 변경함

| 설정 | 가능한 문제 | 확인할 지표 |
| :--- | :--- | :--- |
| 너무 좁음 | 평가 조건을 경험하지 못함 | 조건별 성공률 |
| 적절한 범위 | 변동에 강한 전략 학습 | 반복 평가와 분산 |
| 너무 넓음 | 불가능한 과제·학습 난도 증가 | 실패 사유·학습 안정성 |

- **설정표 예시**

| 변수 | 공칭값 | 범위 예 |
| :--- | :--- | :--- |
| 물체 질량 | 0.20 kg | 0.18–0.22 kg |
| 마찰 계수 | 0.6 | 0.5–0.7 |
| 행동 지연 | 20 ms | 0–40 ms |
| 관측 잡음 표준편차 | 0 rad | 0.005 rad |

- **값을 바꾸는 시점**

| 시점 | 예 |
| :--- | :--- |
| 시작 시 | 에셋·상수 설정 |
| 에피소드 리셋 | 질량·마찰·카메라 포즈 (환경 ID별 적용) |
| 매 스텝 | 센서 잡음 |
| 일정 간격 | 외력·배경 변화 |

- **파라미터 스윕 관찰**
	- 마찰이 클수록 관절 속도가 빠르게 0으로 수렴함
	- 감쇠가 작으면 오버슈트·진동, 크면 느리게 수렴함
	- 강성이 낮으면 목표에 도달하지 못하고(정상상태 오차), 높으면 오버슈트함
	- 지연이 클수록 응답이 늦어짐 (그래프 범례: 6 step = 17 ms, 48 step = 133 ms)

- **태스크 가능 범위 검사**: 목표가 도달 범위 안에 있는지, 물체가 관측 가능한지, 랜덤화 후 충돌·초기 침투가 없는지 확인

### 2. 효과 검증과 평가

- **절제 실험** ⭐

| 조건 | 변경점 | 고정할 항목 |
| :--- | :--- | :--- |
| 기준 | 랜덤화 없음 | 정책·학습 예산·평가 |
| 전체 DR | 선택한 축 모두 | 같은 평가 조건 |
| 한 축 제거 | 지연 등 한 축 OFF | 다른 축과 예산 |
| 범위 비교 | 좁게·넓게 | 평가 프로토콜 |

- 여러 시드의 흔들림도 확인하고, 축 사이 상호작용은 따로 검사함
- **훈련과 평가 구분**: 훈련 분포(수정 가능) / 검증 조건(선택에 사용했다고 기록) / 최종 시험(튜닝 후 고정) / 실물 시험(장비·안전 기준 적용) ⭐
- **커리큘럼·ADR**: 쉬운 범위에서 시작하고 경계 조건의 성능을 보고 범위를 확대함 (확대 속도와 되돌림 규칙 기록)
- **실패 분석** ⭐
	- 실패 사례는 로봇의 **약점**으로 분석하며, 하드웨어 또는 소프트웨어 수정 근거가 됨
	- 예: 엔드 이펙터 회전 축 추가, 다이나믹셀 기어비 조정으로 이동 속도 향상
	- 시뮬레이션 학습은 프로토타입의 하드웨어 결함 검증에도 사용함

### 3. Isaac Sim / Isaac Lab

- **역할**: Isaac Sim은 장면·물리·센서 출력을 계산하고, Isaac Lab은 관측·행동·보상·리셋을 구성해 학습시킴
- **시뮬레이션 사용 이유**: 실물 실행 전 충돌·실패 확인(48V급 모터부터 화재 위험), 실물에서 얻기 어려운 상태(센서 노이즈, 강풍 등) 재현

| 항목 | 시뮬레이션 | 실물에서 확인할 것 |
| :--- | :--- | :--- |
| 물리 | 계산 결과 (질량·마찰은 부정확, 마찰 재현이 특히 어려움) | 질량·마찰·지연 차이 |
| 렌더 | RGB·깊이·분할 라벨 (가림·반사 재현 한계, GPU 자원 필요) | 노출·가림·깊이 결손 |
| 반복 | 초기 상태를 정확히 재설정 | 재배치 오차 |
| 성공 판정 | 자동 조건 검사 | 실제 작업 요구와 일치 |

- **OpenUSD** ⭐
	- Stage: 조합된 전체 장면 / Prim: 경로로 찾는 장면 요소 / Attribute: 위치·재질 등 속성
	- 경로 예: `/World/Ground`, `/World/Robot/base_link`, `/World/Target`, `/World/Camera` (TF 구조와 유사)
	- Reference: 다른 USD 파일(공용 로봇 에셋)의 내용을 Prim으로 불러오는 연결
	- 팀원 모두 같은 공용 USD를 참조하고, 실험별 변경은 별도 레이어에서만 수행함 (파일이 다르면 다른 모델·다른 학습 결과)
	- 경로는 절대 경로를 사용하고, 파일 이동 시 참조 경로를 확인함
	- 로봇 내부 구조는 URDF로 정의함 (USD + URDF 혼합)

- **URDF 점검 체크리스트** ⭐
	- 실제 형상·설계도와 일치하는지 확인
	- 단위는 m·kg (cm·mm 혼용 시 스케일 오류)
	- 재질·밀도: 3D 프린터 출력물은 필라멘트 제조사 물성값, 로보티즈 부품은 제공된 재질 정보 사용
	- 관절 타입·축·한계 (회전해야 할 관절이 fixed이면 움직이지 않음)
	- 충돌 형상, 관절 드라이브(강성·감쇠·출력 제한) 입력 (이전 실습 URDF에는 없었음)
	- CAD 변환 애드온(Fusion 360, SolidWorks) 사용 후 결과 점검

- **관절 드라이브**: 정책이 목표각을 내보내고 드라이브가 추종함 (ROS에서 관절 각도 명령을 토픽으로 보내던 것과 같은 개념)
- **센서**
	- 카메라: RGB / Depth / 분할 라벨 출력, ROS 브리지로 토픽 발행 가능
	- 접촉 센서: 접촉 여부와 힘 확인 (팀 로봇에는 없음)
	- **정책 관측과 진단 정보를 분리함**: 정책에는 실행 때 얻는 관측만 전달하고, 참값(ground truth)은 보상·평가·디버깅에만 사용함

### 4. 태스크 구성

- **태스크 명세 다섯 항목**

| 항목 | 설계 질문 | 예 |
| :--- | :--- | :--- |
| 장면 | 무엇을 배치하는가 | 회전축·목표·카메라 |
| 관측 | 무엇을 측정하는가 | 각도·속도·목표 오차 |
| 행동 | 무엇을 명령하는가 | 목표각 변화량 |
| 보상·판정 | 어떤 결과를 원하는가 | 추종·정착·제한 준수 |
| 리셋 | 언제 다시 시작하는가 | 시간 초과·실패·초기각 |

- **Manager vs Direct**
	- Manager: 관측·행동·보상 항목(Term)을 분리하고 설정으로 조합·교체함, 항목별 단위·가중치 점검
	- Direct: 환경 클래스 하나에 계산 흐름을 직접 작성하며 리셋·버퍼·종료 처리를 명시함
- **병렬 환경**: 관측 shape는 (환경 수, 관측 차원), VRAM에 따라 환경 수가 제한됨 (강사 경험: 8GB에서 16개)
- **물리 주기와 정책 주기**: policy dt = physics dt × decimation (0.005 s × 4 = 0.02 s → 물리 200 Hz, 정책 50 Hz) ⭐
- **학습 전 검사 5가지**: 중력·단위(단일 물체 낙하), 관절(한 축씩 목표 변화), 센서(정지 장면 반복), 리셋(서로 다른 환경 종료), 보상(성공·실패 수동 생성)
- **세대(Generation)와 보상 추적**
	- 1세대 학습 결과가 다음 세대에서 보장되지 않음
	- 세대 중간의 보상 하락(예: -11점)과 일부 환경의 실패는 정상이며, 임계 점수(예: 5점 만점에 3.2점)로 다음 세대 진행을 판단함
	- 리셋 조건(실패 각도, 버틴 시간, 시간 초과)을 기록함

## 알게 된 것

- DR의 핵심은 범위 설정이며, 범위에는 단위·상한·하한·근거가 필요
- 효과는 절제 실험(한 축 제거)과 여러 시드 비교로 검증하고, 최종 시험은 튜닝 후 고정함 ⭐
- 실패 사례는 폐기하지 않고 하드웨어·소프트웨어 개선 근거로 사용
- 팀 전체가 같은 공용 USD를 참조하고, 실험별 변경은 별도 레이어에서만 수행함
- 정책 관측과 참값을 분리할 것
- URDF는 단위(m·kg), 재질/밀도, 관절 타입, 충돌 형상, 드라이브를 점검해야함
- 태스크는 장면·관측·행동·보상·리셋 다섯 항목으로 구성함
