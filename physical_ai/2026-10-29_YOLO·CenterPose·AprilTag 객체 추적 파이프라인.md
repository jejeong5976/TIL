### 1. 목표와 환경

- 목표: 검출 상자·태그 ID·물체 자세를 같은 시각·같은 좌표계로 연결하고, 가림 후에도 동일 물체를 판단하며, 측정이 오래되면 행동을 중지
- 핵심 미션: 그리퍼(TCP)·손가락이 물체나 태그를 가렸을 때의 처리 ⭐
- 실습 순서: 카메라·보정 확인 → AprilTag 확인 → YOLO 검출·추적 → CenterPose 공식 모델 → 자체 데이터 라벨·학습 → ONNX/TensorRT 비교 → ID·6D 자세 연결 → 가림·재등장·정지 시험

| 항목 | 값 |
| :--- | :--- |
| OS | Ubuntu 24.04 (Noble) |
| 추론 장비 | Jetson Orin, JetPack 7.2 |
| 프레임워크 | Isaac ROS 5.0 |
| ROS 2 | Lyrical (LTS, 지원 종료 2031년 5월) |
| YOLO | v8 (ROS 디코더 제공). YOLOv8을 LTS라고 부르지 않음 |

- YOLO26 사용 시 디코더 직접 구현 필요 ⭐
	- 내보내기 설정에 따른 출력 이름·형상·상자 표현 확인
	- 이미 처리된 결과에 NMS 중복 적용 금지
	- letterbox 변환을 원본 픽셀로 복원 → `Detection2DArray` 발행
	- 같은 영상으로 Ultralytics 결과와 비교
	- 파일명만 바꿔서 기존 디코더에 넣지 않음

### 2. 구성 요소별 역할

| 구분 | 질문 | 출력 | 한계 |
| :--- | :--- | :--- | :--- |
| YOLO | 무엇이 어디에 있는가 | 클래스·2D 상자·점수 | 3D 위치·회전·영구 ID 확정 불가 |
| CenterPose | 물체가 어떻게 놓였나 | 회전·이동·상대 크기 (`Detection3DArray`) | 스케일 모호성, 회전 대칭 |
| AprilTag | 이 표식은 몇 번인가 | ID·코너·태그 자세 | 가려지면 검출 불가 |
| PyTorch | 모델을 어떻게 학습하나 | 텐서·자동미분·최적화 | 모델이 아니라 학습 도구 |

- 검출 / 자세 추정 / 추적 구분
	- 검출: 프레임마다 후보를 찾음 (검출 번호는 영구 ID가 아님)
	- 자세 추정: `R`, `t`로 물체 좌표를 표현
	- 추적: 이전 물체와 현재 후보를 연결
	- 출력을 이어 붙이는 것만으로 안정된 ID와 가림 복구가 생성되지 않음
- YOLO는 CenterPose의 필수 전처리가 아님. 클래스 선택·후보 제한·재탐색에 사용 가능
- YOLO ROI를 잘라 CenterPose에 넣는 경우 키포인트 좌표와 `K`를 함께 변환해야 함 (원본 CameraInfo 그대로 사용 시 자세가 틀어짐)
- 태그가 가려진 경우 YOLO 외형 후보를 얻을 수 있으나, 태그를 다시 읽기 전에는 같은 색의 퍽을 같은 ID로 단정하지 않음

### 3. 통합 파이프라인

```
카메라 RGB + CameraInfo
  → YOLO / CenterPose / AprilTag (병렬)
  → 시간 동기화 → 후보 연결 (association)
  → TF 변환 → 추적 상태 + 불확실성
  → 대상 선택 → 행동 허용 판정 → 로봇 제어기
```

- 학습 PC(PyTorch / TAO) → **ONNX** → Jetson에서 **TensorRT 엔진** 생성 → ROS 노드가 추론 결과를 메시지로 발행 ⭐
- TensorRT 엔진은 대상 장비에서 생성
- 학습 프레임워크 / 추론 엔진 / 통신 프레임워크를 구분

### 4. CenterPose

- 구조: backbone → 출력 헤드 → PnP
	- 중심 히트맵 + sub-pixel offset + 2D 상자 크기
	- 키포인트 히트맵(8) + displacement
	- 상대 cuboid 크기(3)
	- 예측한 2D 점과 3D 상자 점을 대응시켜 **PnP**로 6D 자세 계산
- 객체 좌표계와 꼭짓점 순서를 모든 영상에서 동일하게 유지 (화면 왼쪽 점을 매번 1번으로 붙이지 않음)
- 카메라 투영: `p_c = R p_o + t`, `u = f_x X/Z + c_x`, `v = f_y Y/Z + c_y`
- PnP: 재투영 오차를 최소화하는 `R*, t*` 계산

| 오류 원인 | 결과 |
| :--- | :--- |
| 점 순서 오류 | 뒤집힌 자세 |
| `K` 오류 | 거리·방향 오차 |
| 가림 | 부정확한 점 |

- 잔차와 양의 깊이 여부를 검사
- **스케일 모호성** ⭐
	- 큰 물체가 멀리 있는 영상과 작은 물체가 가까운 영상이 비슷하게 보임
	- 상대 크기만으로 절대 거리 확정 금지
	- 실측 치수·깊이·기준 표식으로 검증, ROS decoder의 `cuboid_scaling_factor` 조정 후 여러 거리에서 실제 길이와 비교
- **대칭성** ⭐
	- 원기둥은 축 회전 시 외형 동일, 정사각 기둥은 90° 반복
	- 태그 방향으로 기준을 정할 수 있으나 태그가 가려지면 회전 관측 가능성이 달라짐
	- 라벨 정책에 축·대칭군 명시
- 단안 영상에서 픽셀 오차가 작아도 깊이·스케일이 정확하다고 단정 불가. 왜곡 보정 여부를 함께 기록
- CenterPoseTrack은 시간 필터·불확실성을 쓰는 별도 연구 모델. ROS CenterPose 옵션 변경으로 대체되지 않음

### 5. YOLOv8

- 구조: Backbone → Neck → Head → 여러 크기 특징 결합 → 클래스·상자 예측
- NMS로 중복 상자 제거. IoU = 교집합 면적 / 합집합 면적
- 신뢰도 점수와 IoU 임계값은 서로 다른 역할
- 상자 중심 픽셀은 3D 물체 중심과 일반적으로 다름 → 깊이 또는 자세 추정과 연결 필요
- YOLO 추적: ByteTrack 사용. 2D 추적 성공이 6D 자세 성공을 의미하지 않음

### 6. AprilTag

- 검은 경계·코너 검출 → 내부 비트 패턴으로 ID 해독 → 한 변의 길이와 `K`로 태그 자세 계산
- ID의 의미는 **매핑 파일**(물체명·치수·태그 장착 변환)을 별도로 작성 ⭐
- 태그 `size`: 검은 경계 기준 한 변. 16mm이면 `size = 0.016` m. 흰 여백 포함 20mm와 구분 ⭐
- Isaac ROS AprilTag(CUDA backend)는 `tag36h11` 지원. family가 틀리면 ID가 검출되지 않음
- 입력 `image + camera_info`, 출력 `/tag_detections`, `/tf`
- 인식 거리 추정: 픽셀 크기 ≈ `f_x × 한 변 / 거리`

| 거리 | 픽셀 크기 (f_x=600px, 0.016m) |
| :--- | :--- |
| 0.5m | 약 19.2px |
| 1.0m | 약 9.6px |

- 성공 거리 보장이 아님. 기울기·흐림·노출·해상도에 따라 실패 → 거리별 ID 성공률·자세 오차를 실측
- 태그 → 물체 변환: `T_co = T_ct × T_to`, `T_bo = T_bc × T_co`
	- 60mm 높이 퍽의 윗면과 중심은 약 30mm 차이 → 태그 축 방향·두께 측정 ⭐

### 7. 좌표계 · 보정 · 동기화

- ROS 본체: x 전방, y 왼쪽, z 위 / 카메라 optical: x 오른쪽, y 아래, z 전방
- 길이 m, 각도 rad 통일. 쿼터니언 순서 xyzw 확인. 픽셀 좌표와 미터 좌표 분리
- OpenGL / OpenCV 변환 여부를 학습·평가·ROS에서 일치
- 크롭·리사이즈는 픽셀 좌표계를 바꾸는 연산: `u' = s(u − x₀)`, `f'_x = s f_x`, `c'_x = s(c_x − x₀)` (letterbox padding 있으면 pad 더함). 보정된 `K` 사용과 키포인트 원본 복원을 중복 적용 금지
- `image stamp` 기준으로 관측 연결, 허용 시간차 초과 시 폐기. TF도 관측 시각의 변환 사용

### 8. 데이터와 라벨

- 공개 데이터 선택 ⭐

| 데이터 | 정답 | 용도 |
| :--- | :--- | :--- |
| COCO | 2D 상자 | YOLO 검출 |
| Objectron | 3D 상자 + 카메라 정보 | CenterPose |
| BOP | 모델 + 6D 자세 | 6D 평가 |

- COCO 상자만으로 CenterPose 6D 라벨 생성 불가. BOP 인스턴스 ID를 퍽 클래스 ID로 직접 사용 금지
- 사용 전 확인: 라이선스·인용 / 카테고리·촬영 조건 / 라벨 필드·좌표계·단위 / 학습·평가 분할 (Objectron은 C-UDA-1.0)
- manifest에 출처 URL, 버전, 다운로드 날짜, SHA-256, 원본 split 기록
- **데이터 누수 방지** ⭐
	- 인접 프레임(100번·101번)을 train/test에 나누면 성능이 과대평가됨
	- 촬영 세션·물체·배경 단위로 split 고정 (70/15/15는 시작안)
	- 최종 test는 마지막에만 사용. 새로운 장소·조명·물체를 별도 holdout으로 확보
- **라벨 변환**
	- COCO → YOLO: `cx=(x+w/2)/W`, `cy=(y+h/2)/H`, `bw=w/W`, `bh=h/H`
	- 클래스 ID는 요청 순서로 0부터 재매핑. 이미지 위에 클래스명까지 표시해 검수
	- YOLO txt: `class x_center y_center width height` (0~1, 객체 없으면 빈 파일 가능)
	- BOP 이동 단위 mm → m 변환 (`t_m = t_mm / 1000`), 회전행렬은 배율 변환하지 않음
	- CenterPose JSON: `camera_data`, `projected_cuboid`(9점: 중심 1 + 꼭짓점 8), `scale`. YOLO txt를 이름만 바꿔 사용 불가
- 변환 라벨 20장을 원본 위에 겹쳐 검수 (앞뒤 뒤집힘, 중심 이동, 1,000배 크기 오류)
- AprilTag 의사 라벨: 태그 자세 + 장착 변환으로 생성. 가려지거나 오독된 프레임은 자동 승인 금지. 태그 포즈를 정답으로 쓴 경우 같은 태그 포즈와의 비교는 독립적 정확도 검증이 아님 ⭐
- 합성 데이터(도메인 랜덤화)는 자세·`K`·가림 정보 기록에 유리. 실제 영상에서 실패 분포를 별도 평가
- 가림 데이터는 원본의 일부를 검은색으로 덮어 증강 가능 (강의 설명). 최소 약 1만 장 필요 (강의 설명)

### 9. 학습 · 내보내기

- PyTorch 학습 구조: Dataset → DataLoader → model → loss → optimizer → validation → checkpoint
- 가중치 갱신: `θ ← θ − η ∇θ L`. 학습률이 크면 불안정, 작으면 수렴이 느림
- 학습 루프 순서: `model.train()` → `zero_grad()` → 순전파 → loss → `backward()` → `step()`
- 검증: `model.eval()` + `torch.inference_mode()`, `optimizer.step()` 호출 안 함
- train loss 감소와 val 성능 개선은 별개 → 함께 기록. seed·버전·설정 저장
- YOLO 학습 시작값: `yolov8n.pt`, 작은 배치, 50 epoch, 작은 subset에서 한 배치 확인
- 퍽이 적은 픽셀을 차지하면 촬영 거리·해상도를 먼저 검토. 색이 클래스 기준이면 강한 색 변화 증강 주의
- 공개 가중치 + 자체 데이터(A) vs 공개 데이터 일부 혼합(B)을 같은 holdout에서 비교

| 단계 | 도구·설정 |
| :--- | :--- |
| YOLO ONNX | `yolo export format=onnx imgsz=640 batch=1 dynamic=False nms=False` |
| CenterPose 학습 | TAO GPU 컨테이너, `tao model centerpose train/evaluate/export` |
| CenterPose ONNX | 입력 1×3×512×512, 출력 7개 (bboxes, scores, kps, clses 등) |
| TensorRT | `trtexec --onnx --saveEngine`. FP32 기준 출력 비교 후 FP16 적용 후 재평가 |

- 파싱 성공과 정확도 검증은 다름. 입출력 이름·형상·정규화·후처리를 모델별로 검증

### 10. 추적 상태와 정책

- 연결 모듈: 정규화 → 후보 연결(gating) → 좌표 변환 → 상태 갱신 → 행동 제안
- gating 조건: 시각 차이, 재투영 오차, 태그 ID, 상자 겹침, 예측 위치, 객체 크기, 양의 깊이. 가장 가까운 후보만 선택하면 교차 시 ID가 바뀜
- 칼만 필터: 예측 `x_pred = F x_prev`, 보정 `x_est = x_pred + K(z − H x_pred)`. 회전은 quaternion으로 처리 (Euler 각 평균 금지)
- `track_id`는 추적기 내부 번호, `tag_id`는 물체의 표식 번호. 새 `track_id`가 생겨도 같은 `tag_id`로 확인 가능. 겹친 상자에 태그가 동시에 들어가면 연결 보류 ⭐
- 상태 전이: `SEARCH → CONFIRM → TRACK`, 미검출 → `LOST`, 재검출 → `CONFIRM`, ID 충돌·오래된 측정 → `HOLD`
- 임계값 시작값: 연속 확인 3프레임, 유효 관측 최대 나이 0.3초, 허용 위치 변화 0.15m (속도·FPS·지연에 맞춰 조정)
- 새 관측 없이 마지막 자세로 계속 움직이지 않음 ⭐
- 신뢰도 점수를 실제 성공 확률로 해석하지 않음
- 규칙 정책과 RL 정책은 다른 문제. 지각 모델과 제어기 경계 유지
- 모델 단독 FPS를 더해도 통합 FPS가 되지 않음. 큐가 쌓이면 오래된 영상을 버리고 최신 관측 우선

### 11. 평가와 실패 점검

- 지표: 검출(Precision·Recall·mAP) / 자세(위치·회전·재투영 오차, 3D IoU) / 추적(ID 교체, 재획득 시간) / 통합(목표 선택 정확도, 가림 후 복구율, 관측 나이 p95)
- 구성별 비교(ablation): A 태그만 / B YOLO+2D 추적 / C CenterPose+시간 연결 / D 통합 (태그 보임·가림, 원기둥·직육면체 구분하여 평가)
- 실패 점검 순서: 한 번에 하나의 조건만 바꾸고 같은 rosbag으로 재검증

| 증상 | 점검 |
| :--- | :--- |
| 검출 없음 | 클래스·조명·해상도 |
| 자세 뒤집힘 | 점 순서·축·`K` |
| 거리 배율 오류 | 실측 크기·단위 |
| 태그 없음 | family·크기·흐림 |
| ID 교체 | 연결 임계값·시간차 |
| 영상 멈춤 | QoS·topic·GPU 메모리 |
| 오래된 명령 | stamp·큐·TTL |

## 알게 된 것

- YOLO는 2D 검출, CenterPose는 3D 자세, AprilTag는 ID와 기준 기하 정보를 담당. 어느 하나로 3D 위치·영구 ID·가림 복구를 모두 해결할 수 없음
- 검출 번호·`track_id`는 영구 ID가 아니며, 가림 후 ID 확정은 `tag_id` 재확인과 시공간 조건으로 판단 
- 스케일 모호성과 회전 대칭 때문에 CenterPose 단독 결과를 신뢰하지 않고 실측·태그로 검증
- 라벨 좌표계·단위·점 순서 오류는 학습 전에 원본 영상 재투영으로 검수해야 함 ⭐
- 데이터 분할은 프레임이 아니라 세션 단위로 해야 누수가 없음
- 파싱 성공(ONNX/TensorRT)과 정확도 검증은 별개이며 같은 입력으로 출력 값을 비교
