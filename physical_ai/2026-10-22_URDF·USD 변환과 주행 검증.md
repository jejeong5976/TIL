- **실제 사례**: M38 CAD 기반 9링크·8관절 모델 (스워브 구동 방식, 4 kg 가정)

### 검증 범위
- 검증 대상: 본체·조향부·바퀴의 상대 움직임
- 가정 조건: 평지, 저속, 총질량 4 kg
- 팔은 현재 CAD 자세로 고정함
- 강도·체결·배선은 별도 검증이 필요함 ⭐
- 학습 전에 모델 파일이 시뮬레이션에서 물리적으로 동작하는지 먼저 확인함

### 형식과 엔진의 역할

| URDF | 로봇 링크·관절 기술 | 트리, 좌표, 관성, 메시 |

### CAD 부품을 링크로 묶는 기준
- 서로 고정된 부품은 같은 링크로 묶음
- 움직이는 경계에 관절을 둠
- 모든 CAD 바디는 정확히 한 링크에 속해야 함 ⭐
- 링크 분할 수준(구동 단위 / 기어·부속 단위)은 팀이 먼저 결정함
	- 세분화할수록 검증 범위는 넓어지고 시뮬레이션 성능은 떨어짐 → 타협점 필요

```
base_link
  lh1_steer → lh1_wheel
  rh1_steer → rh1_wheel
  lh2_steer → lh2_wheel
  rh2_steer → rh2_wheel
```

### 단위·좌표 통일 ⭐
- CAD mm → m: 1,000으로 나눔 (누락 시 크기 1,000배 차이)
- ROS 기준: X 전방, Y 좌측, Z 위쪽
- 월드 좌표 메시에서 링크 원점을 뺌

```python
v_local = C @ v_CAD_mm / 1000 - origin_m
C = [[0, 1, 0], [-1, 0, 0], [0, 0, 1]]
# [100, 200, 30] mm → [0.2, -0.1, 0.03] m
```

- 파일 포맷
	- f3d(Fusion 360)는 사용 불가, STL 또는 STEP으로 내보냄
	- STL: 표면을 삼각형으로 분할, 용량 최소, 삼각형이 클수록 품질 ↓
	- STEP: CAD 표준 포맷, 재질 정보 포함
- 로봇의 초기 위치(home)를 파일에 정의해야 함

### 관절 원점과 회전축
- `origin`: 부모 링크 기준 관절 위치·방향
- `axis`: 관절 좌표계 기준 회전 방향
- 거울 배치된 오른쪽 모듈은 축 부호를 확인해야 함 ⭐
- 0, +0.3, −0.3 rad에서 바퀴 중심과 방향을 비교함 (독립 FK 확인)

```xml
<joint name="hinge" type="revolute">
  <parent link="base_link"/>
  <child link="arm_link"/>
  <origin xyz="0 0 0.1" rpy="0 0 0"/>
  <axis xyz="0 0 1"/>
  <limit lower="-1.5707963" upper="1.5707963" effort="1" velocity="1"/>
</joint>
```

### visual / collision / inertial
- `visual`: 화면에 보이는 메시와 색 (색은 설명용 추정 재질)
- `collision`: 접촉 계산용 단순 형상 (바퀴는 원통, 외형 부품은 박스 근사)
- `inertial`: 질량·질량중심·관성
- 충돌 계산은 collision을 사용하므로 visual과 별도로 정의함

| M38 링크 | 개수 | 각 질량 | 합계 |
|---|---|---|---|
| base_link | 1 | 1.8 kg | 1.8 kg |
| steer | 4 | 0.4 kg | 1.6 kg |
| wheel | 4 | 0.15 kg | 0.6 kg |
| 전체 | 9 | 가정값 | 4.0 kg |

### USD 물리 모델 구성

| 대상 | 필요한 설정 |
|---|---|
| Stage | metersPerUnit=1, upAxis=Z, kg=1 |
| /Robot | defaultPrim, ArticulationRootAPI |
| 각 링크 | RigidBodyAPI, MassAPI |
| 충돌 도형 | CollisionAPI |
| 관절 | RevoluteJoint + body0/body1 관계 |
| 장면 | PhysicsScene / 바닥은 시험에 맞게 추가 |

### URDF ↔ USD 관절 대응 ⭐

| 항목 | URDF | USD |
|---|---|---|
| 회전 한계 | radian | degree |
| 연결 | parent / child | body0 / body1 |
| 관절 위치 | origin | localPos0 / localPos1 |
| 축 방향 | axis + origin rpy | axis + localRot0/1 |
| 90° 예 | 1.5707963 | 90.0 |

### 실습
- **실습 1 (환경 준비)**: venv(Python 3.11) 생성 → `requirements.txt` 설치 → `lab.py build` → `lab.py check`
- **실습 2 (값 변경과 재생성)**
	- `model.json`의 arm 질량 0.2→0.3 → 두 형식의 질량이 함께 변경되는지 확인
	- `joint.origin`의 z 0.1→0.12 → URDF origin과 USD localPos0 변경 확인
	- build 후 check → `PASS_STATIC` 출력, 이후 원래 값으로 복원해 재생성
- **실습 3 (단위 오류 검출)**: `lab.py self-test`
	- 정상 모델: `PASS_STATIC`
	- USD 상한을 90° 대신 1.5707963으로 변경 → `angle unit mismatch` 검출
- **실습 4 (결과 재판정)**: `check_recorded_results.py`로 기록된 결과를 재판정

### 주행 검증

**MuJoCo**
- 마찰계수 0.3 / 0.6 / 0.9
- 동작 4종(전진·횡이동·대각선·제자리 회전) × 마찰 3종 = 12개 조건 → 모두 PASS
- dt = 0.002 s, 각 시험 10 s
- 바닥 재질(카펫 등)은 입력하지 않고 마찰계수 값으로 대체함

**Isaac Sim (PhysX)**
- SimulationApp 초기화 후 모듈 import
- `m38.usd`를 참조해 articulation 구성
- DOF 이름으로 관절 순서 매핑
- 원래 drive gain을 0으로 하고 effort로 제어
- 시험마다 상태·속도·적분값 초기화
- 영상은 저장된 PhysX 기록을 MuJoCo 렌더러로 재생한 프레임임. 판정은 원본 로그에서 확인함

**합격 기준 (Isaac)**

| 항목 | 기준 |
|---|---|
| 위치 / yaw 오차 | < 0.05 m / < 5° |
| 기울기 / 정지 속도 | < 10° / < 0.02 m/s |
| 조향 / 바퀴 각속도 | ≤ 1.001 / ≤ 10.001 rad/s |
| 최종 토크 | ≤ 1.000001 N·m |
| 수치 상태 | 유한값 / 수치 불안정 없음 |

**결과 ⭐**

| 시험 | 위치 오차 (mm) | 최대 조향 (rad/s) | 결과 |
|---|---|---|---|
| 전진 | 2.662 | 0.9314 | PASS |
| 횡이동 | 3.182 | 0.9016 | PASS |
| 대각선 | 4.349 | 1.0142 | FAIL |
| 회전 | 0.422 | 0.9846 | PASS |

- 대각선은 위치 오차(4.349 mm)가 기준(0.05 m)보다 훨씬 작지만 FAIL임
- FAIL 원인: 최대 조향 각속도 1.0142 rad/s가 제한 1.000 rad/s를 초과
- 도착했어도 속도·토크 제한을 넘으면 FAIL
- 개선 실험: 조향 목표 변화율을 줄이고 재시험

## 알게 된 것

- 링크 분할 수준은 URDF 작성 전에 정하며, 세분화와 시뮬레이션 성능은 상충함
- mm→m 변환과 Z-up 축 정렬을 놓치면 이후 검증 결과가 모두 틀어짐 ⭐
- URDF는 radian, USD는 degree를 사용하므로 회전 한계 변환이 필요함 ⭐
- 정적 검사가 PASS여도 주행 검증은 별도로 통과해야 함
- 위치 오차가 작아도 속도·토크 제한 초과 시 FAIL이며, 원인은 하드웨어가 아니라 제어 파라미터(조향 목표 변화율)로 분석함 ⭐
- 기록 판정은 다운샘플 전 모든 step의 최대값으로 해야 순간 초과를 놓치지 않음
