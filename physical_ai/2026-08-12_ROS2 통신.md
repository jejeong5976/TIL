### [10강] Topic 통신과 노드 작성
- **Topic 특성**

| 항목 | 내용 |
|---|---|
| 통신 방향 | 단방향, 비동기, 다대다 |
| 결합도 | 느슨한 결합 — 발행자는 구독자 존재/수를 모름 |
| 큐 깊이(depth) | 버퍼링 개수. 초과 시 오래된 메시지부터 삭제 |
| 큐 깊이 설계 | 센서 스트림 → 작게(1~10, 최신값 우선) / 명령 → 크게 |

- **노드 작성 4단계 (rclpy·rclcpp 공통)**
```
Node 상속 → publisher/subscriber 생성 → 콜백 정의 → spin
```

-  **실습 코드 — publisher.py**
```python
import rclpy
from rclpy.node import Node
from geometry_msgs.msg import Twist

class VelocityPublisher(Node):
    def __init__(self):
        super().__init__('velocity_publisher')
        self.pub = self.create_publisher(Twist, '/cmd_vel', 10)   # (메시지타입, 토픽명, 큐깊이)
        self.timer = self.create_timer(0.05, self.tick)            # 0.05초(20Hz)마다 tick 호출
        self.get_logger().info('발행 시작')

    def tick(self):
        msg = Twist()
        msg.linear.x = 0.2   # 0.2 m/s 전진
        msg.angular.z = 0.1  # 약간 회전
        self.pub.publish(msg)

def main():
    rclpy.init()
    rclpy.spin(VelocityPublisher())   # 타이머 콜백을 실제로 돌림 (이벤트 구동)
    rclpy.shutdown()
```

-  **실습 코드 — subscriber.py**
```python
import rclpy
from rclpy.node import Node
from geometry_msgs.msg import Twist

class VelocitySubscriber(Node):
    def __init__(self):
        super().__init__('velocity_subscriber')
        self.sub = self.create_subscription(Twist, '/cmd_vel', self.on_cmd, 10)  # (타입, 토픽명, 콜백, 큐깊이)

    def on_cmd(self, msg):   # 메시지 도착마다 executor가 호출
        self.get_logger().info(f'받음: 전진 {msg.linear.x:.2f} m/s, 회전 {msg.angular.z:.2f} rad/s')

def main():
    rclpy.init()
    rclpy.spin(VelocitySubscriber())
    rclpy.shutdown()
```


- **확인 명령어**

| 명령어 | 의미 |
|---|---|
| `ros2 topic list` | `/cmd_vel` 토픽이 등록됐는지 확인 |
| `ros2 topic echo /cmd_vel` | 실제 발행되는 메시지 내용 실시간 출력 |

-  publisher.py 실행 후 위 명령어를 통해 토픽 발행을 확인함.
-  subscriber.py 실행 후 로그로 수신을 확인함.


### [11강] Service·Action·Parameter 통신

- **패턴 선택 기준**

| 질문 | 답 → 패턴 |
|---|---|
| 결과를 안 돌려받음 | Topic |
| 결과를 즉시 돌려받음 | Service |
| 오래 걸리고 진행상황·취소 필요 | Action |
| 노드의 설정값을 다룸 | Parameter |

- **Service**
	- 요청 → 응답
	- ⚠️ 주의할 것
		- 콜백 안에서 서비스 응답을 **동기 대기하면 데드락** (executor가 이미 콜백에 붙잡혀 있음)
		  → 해결: `call_async()` + `spin_until_future_complete()` 사용

```python
future = client.call_async(request)              # 비동기 요청
rclpy.spin_until_future_complete(node, future)    # 응답까지 spin
result = future.result()
```

- **Action**
	- Service(목표/결과) + Topic(피드백 스트림)
	- 흐름: `Goal → Feedback(반복 전송) → Result`, 언제든 **취소** 가능
		- 취소가 중요한 이유
			- 로봇이 물리적으로 움직이는 중 즉시 멈춰야 하는 상황 대응 (예: Nav2 자율주행)


### [13강] QoS 정책과 DDS 미들웨어

- **DDS 미들웨어**
	- ROS2 통신의 실제 전송 계층 = DDS(Data Distribution Service)
	- 중앙 마스터 없는 **분산 디스커버리** → 한 노드가 죽어도 나머지는 계속 통신 (단일 장애점 없음)

- **QoS 3대 정책**

| 정책              | 옵션              | 설명                        | 적합한 데이터                      |
| --------------- | --------------- | ------------------------- | ---------------------------- |
| **Reliability** | Reliable        | 유실 시 재전송, 지연 가능           | 명령, 설정 (`/cmd_vel`)          |
|                 | Best-Effort     | 유실 허용, 최신 우선              | 센서 스트림 (카메라, LiDAR)          |
| **Durability**  | Volatile        | 접속 후 메시지만 수신              | 대부분의 스트림                     |
|                 | Transient Local | 마지막 메시지 보관 → 늦은 구독자에게도 전달 | `/map`, `/robot_description` |
| **History**     | Keep Last(N)    | 최근 N개만 보관                 | 일반적                          |
|                 | Keep All        | 자원 한도 내 모두 보관             | —                            |

-  **미리 정의된 프로파일**

| 프로파일                | 구성                                 | 용도           |
| ------------------- | ---------------------------------- | ------------ |
| Default             | Reliable, Volatile, KeepLast(10)   | 일반 명령        |
| Sensor Data         | Best-Effort, Volatile, KeepLast(5) | 카메라, LiDAR   |
| Services/Parameters | Reliable                           | 서비스, 파라미터 통신 |

#### QoS 호환성 규칙 ⭐
> **구독자의 요구가 발행자보다 엄격하면 연결되지 않는다.**

| 발행자         | 구독자         | 결과     |
| ----------- | ----------- | ------ |
| Best-Effort | Reliable    | 연결 안 됨 |
| Reliable    | Best-Effort | 연결됨 ⭐  |
- 센서 노드가 Best-Effort로 메세지 publish + 구독자가 Reliable → 토픽은 잘 되는데 데이터가 안 옴
- 진단 명령
	- `ros2 topic info /토픽명 --verbose` → 발행자 - 구독자 QoS 비교 가능


### [14강] TF2 좌표 변환

- **왜 좌표계가 여러 개인가**
	- 부품·센서마다 자기 기준점(frame)이 다름 (LiDAR, 카메라, 바퀴 제어, 경로 계획 각각 다른 기준)
	- TF2(Transform Library 2)가 이 관계들을 트리(tree)로 관리

- **표준 좌표계 계층**
```
map (전역 고정) → odom (주행 기준) → base_link (로봇 몸체) → 센서 링크들 (lidar_link, camera_link, imu_link)
```

| 프레임       | 특징                                                     |
| --------- | ------------------------------------------------------ |
| map       | 절대 위치 기준, 시간 지나도 안 움직임                                 |
| odom      | 로봇의 출발점 기준으로 엔코더(바퀴 회전)로 추정한 위치, 부드럽지만 시간이 지나면 오차가 누적됨 |
| base_link | 로봇 몸체의 기준점, 모든 센서가 여기 상대적으로 고정 장착됨                     |
| 센서 링크들    | 각 센서의 위치, base_link에 고정됨                               |

### 실습 - robot.urdf

- 튜터님이 주신 코드 참고해서 바퀴 추가 해봄!

- **Link 구성**

| Link                                 | Geometry                 | 역할           |
| ------------------------------------ | ------------------------ | ------------ |
| base_footprint                       | * visual X               | 지면 기준 가상의 원점 |
| base_link                            | box 1×1×0.5              | 로봇 몸체        |
| lidar                                | cylinder r=0.05, len=0.1 | LiDAR 센서     |
| left_front_wheel / right_front_wheel | cylinder r=0.2, len=0.05 | 앞바퀴          |
| left_back_wheel / right_back_wheel   | cylinder r=0.2, len=0.05 | 뒷바퀴 - 구현해봄   |

- **Joint 구성**

| Joint | type | parent → child | origin xyz | axis |
|---|---|---|---|---|
| base_footprint_joint | fixed | base_footprint → base_link | 0 0 0.4 | — |
| lidar_joint | fixed | base_link → lidar | 0 0 0.3 | — |
| left_front_wheel_joint | continuous | base_link → left_front_wheel | -0.525 0.3 -0.2 | x축 |
| right_front_wheel_joint | continuous | base_link → right_front_wheel | 0.525 0.3 -0.2 | x축 |
| left_back_wheel_joint | continuous | base_link → left_back_wheel | -0.525 -0.3 -0.2 | x축 |
| right_back_wheel_joint | continuous | base_link → right_back_wheel | 0.525 -0.3 -0.2 | x축 |

- `fixed`: 위치 고정
- `continuous`: 4개 바퀴 조인트 — x축 기준 제한 없이 회전 가능 (바퀴 굴러가는 축)
- 바퀴 origin의 `rpy="0 1.5735 0"` / `"1.5735 0 1.5735"`는 실린더 형상을 y축 방향으로 눕혀서 바퀴처럼 보이게 하는 회전값 (약 90°) ⭐
