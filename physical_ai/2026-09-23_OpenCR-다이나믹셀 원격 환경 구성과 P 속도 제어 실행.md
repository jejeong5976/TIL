### OpenCR·다이나믹셀 원격 빌드·업로드 환경

- **원격 작업 구성**
	- 라즈베리파이(Ubuntu Server 22.04, `aarch64`)에 SSH로 접속해 원격에서만 작업
	- PC는 SSH 접속 용도로만 사용

- **빌드** 
	- OpenCR 공식 보드매니저는 ARM Linux 호스트용 컴파일러·업로더를 제공하지 않음
	  → 라즈베리파이에서 `arduino-cli`(1.5.1)와 OpenCR 코어(1.5.3)를 수동 설치
	- Ubuntu 제공 크로스 컴파일러(`arm-none-eabi-g++`)로 과제 소스(`opencr_position_p.ino`) 직접 빌드 (FQBN: `ROBOTIS:OpenCR:OpenCR`)
	- 업로더(`opencr_ld`)도 OpenCR 저장소의 소스를 라즈베리파이에서 직접 빌드해서 사용

| 구분        | 내용                         | 비고                          |
| --------- | -------------------------- | --------------------------- |
| 대상 모터     | XM430-W350 (모델 1020)       | ID 12, 1 Mbps, Protocol 2.0 |


- **P 제어 방식**
	- 펌웨어는 다이나믹셀을 velocity mode로 두고 P 제어로 속도 명령(`u_deg_s`)을 계산해 전송
	- 시리얼 명령: `s <Kp> <speed_deg_s|max> <angle_deg>`(설정+시작), `x`(정지)

```text
s 1.0 30 30   # Kp=1.0, 속도상한 30 deg/s, 목표 30°(상대)
x             # 정지
```

- **실행 결과**
	- Kp=1.0, 목표각 30°(상대), 속도상한 30 deg/s로 실행
	  → `position_deg`가 0°에서 29.443°까지 수렴, 목표와의 잔류 오차 0.557°에서 더 변화 없이 정지 상태 유지

- **정지 확인 방법**
	- 정지는 `x` 입력 후 `STOP: user` 메시지로만 확인 가능

## 알게 된 것

- OpenCR 공식 보드매니저가 ARM Linux 호스트를 지원하지 않아, 라즈베리파이에서 `arduino-cli`+크로스컴파일러로 직접 빌드·업로드해야 함 or waffle-pi가 아닌 waffle 이용
- 과제명은 "P 위치 제어"지만 실제 펌웨어는 velocity mode 기반 P 속도 제어 방식임 ⭐
